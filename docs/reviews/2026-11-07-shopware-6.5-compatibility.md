# Shopware 6.5 compatibility review

**Date:** 2026-11-07 · **Against:** Shopware 6.5.6.1 · **Reference:** Shopware 6.7.12.1, the version the app
and `LaioutrConnector` were built and tested on.

## Scope and method

Every Store API and Admin API call the app makes, every response field its mappers read and every error
code it branches on was compared between the 6.5.6.1 and 6.7.12.1 sources. The same was done for the
connector plugin: classes, events, routes, Twig blocks and the storefront DOM its script depends on.

Findings were then reproduced on a local 6.5.6.1 instance in `APP_ENV=prod`. Prod matters because one of
them only exists where the object cache is real. Read-only calls against a production 6.5.6.1 shop settled
the remaining catalog questions on real data.

All 29 Store API routes the app calls exist on 6.5.6.1. Every incompatibility below is in parameters,
response semantics or error codes.

## App: fixed

| Finding                                          | On 6.5.6.1                                                                                                                                                                                                                                    | Fix                                                                                                                    |
| ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `ProductSearchQuery` paging and built-in filters | `CachedProductSuggestRoute` keys on the criteria hash before the listing processors apply `p`, `min-price`, `max-price`, `manufacturer` and `shipping-free`. Page 1 is served page 2, and an unfiltered search is served a filtered total.    | Read `/search`, whose cache key is taken after those parameters are applied. Search now also sends the chosen sorting. |
| `ProductsByCategoryIdQuery` paging               | `PagingListingProcessor` defaults `p` to 1 and overwrites the offset that `page` set.                                                                                                                                                         | Send `p`.                                                                                                              |
| Unknown sort key                                 | `SortingListingProcessor` answers 404 `PRODUCT_SORTING_NOT_FOUND` and the whole listing fails. 6.7 falls back to the default sorting.                                                                                                         | `withSortingFallback` retries without `order` on that code, for both listings and search.                              |
| Logout                                           | With `core.loginRegistration.invalidateSessionOnLogOut` off (the default), `LogoutRoute` mints a new token but leaves the old one bound to the customer. The embedded checkout's storefront session holds the same token and stays logged in. | Send `replace-token: true`. 6.7 always replaces the token and ignores the field.                                       |
| Register with an over-long value                 | No maximum-length validation. The value reaches the database and comes back as a 500 with MySQL error 1406. `customer_address` is narrower on 6.5: `first_name` 50, `last_name` 60, `city` 70.                                                | `throwAsInvalidField` maps error 1406 to `InvalidFieldError('TOO_LONG')` on the field that owns the column.            |

## App: fixed, broken on every version

| Finding                                                                                                                                                        | Fix                                                             |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| `CustomerGetCurrentAction` read `id` and `firstName` off the `{ data, status }` wrapper `invoke` returns, so both came back undefined.                         | Read `response.data`, and request the `salutation` association. |
| `CreateReviewAction` compared the status with 200, but the route answers 204, so every saved review reported failure.                                          | Success is the call resolving.                                  |
| Cart tax added the deliveries' taxes on top of `price.calculatedTaxes`, which already cover shipping (`AmountCalculator` merges positions and shipping costs). | Use `price.calculatedTaxes` only.                               |
| Guest wishlist detection matched only `CHECKOUT__CUSTOMER_NOT_LOGGED_IN`; 6.7 answers `FRAMEWORK__ROUTING_CUSTOMER_NOT_LOGGED_IN`.                             | Match both codes.                                               |
| Wishlist totals were the page's row count.                                                                                                                     | Send `total-count-mode: exact`.                                 |
| Review dates were `Invalid Date`, because `createdAt` was not in `includes`.                                                                                   | Include it.                                                     |
| `ProductsByCategorySlugQuery` pre-loaded variants without `maxLimit`, so variants past the first page were missing.                                            | Pass `maxLimit`.                                                |

## App: open, lower impact

- **Currency header:** `sw-currency-id` is ignored by the 6.5 Store API; 6.7.2.0 added it. Harmless on a
  single-currency shop. On a multi-currency 6.5 shop, amounts are priced in the context currency while the
  app labels them with the visitor's.
- **Thumbnail sizes:** 6.5 stores the configured box size (`400x400`, `800x800`, …), not the real image size.
  `mediaMapper` and the image provider pick and report sizes from those values.
- **Category scope:** `/category` is not limited to the sales channel's navigation, footer and service trees,
  so other channels' categories appear in `CategoryAllQuery` and the Studio picker.
- **Missing navigation category:** a missing footer or service category answers 400 instead of an empty 204.
- **Newsletter:** `customFields` are dropped. For logged-in customers, double opt-in checks only
  `doubleOptInRegistered`.
- **Inactive customers:** a customer who has not confirmed a double-opt-in registration stays inactive.
  Password recovery then finds no active customer and sends nothing, and the action reports success
  anyway, as it does for an unknown address.
- **Reviews:** they are served even when `core.listing.showReview` is off.

## Connector

| Finding                                                                                                                                                                                                                                                                                                                          | Status                                                                                                                                                         |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Controllers used `Symfony\Component\Routing\Attribute\Route`. 6.5 ships `symfony/routing` 6.3, which has no `Attribute\` namespace and only reads `Annotation\Route`, so all five routes were silently dropped. `base.html.twig` then threw on `path('frontend.laioutr.checkout-order')` and every storefront page answered 500. | **Fixed.** Routes are declared in `routes.yaml`. `Annotation\Route` would have worked on 6.5, but Symfony 7.4 (Shopware 6.7) deprecates it and 8.0 removes it. |
| `composer.json` required `shopware/core` and `shopware/storefront` `~6.6.0 \|\| ~6.7.0`, and PHP `~8.2.0` or later.                                                                                                                                                                                                              | **Fixed:** `~6.5.0` and `~8.1.0` added. Static analysis at `phpVersion: 80100` is clean.                                                                       |
| `shopware.navigation.id` does not exist on 6.5, so `data-navigation-id` rendered empty.                                                                                                                                                                                                                                          | **Fixed:** falls back to `page.header.navigation.active.id`.                                                                                                   |
| 6.5.6.1's own `config.xsd` is rejected by libxml 2.13+ ("content model is not determinist").                                                                                                                                                                                                                                     | **Open, environmental.** This blocks installing any plugin with a `config.xml` on such a host, not only this one. Check `LIBXML_DOTTED_VERSION` on the target. |
| The integration suite targets PHPUnit 12. 6.5 core's test traits need PHPUnit 9.6 and read `@before` docblocks.                                                                                                                                                                                                                  | **Open.** CI covers 6.6 and 6.7 only. The 90 unit tests pass against the 6.5.6.1 vendor.                                                                       |

The payment and return-trip design holds on 6.5. `CheckoutController::order()` and `finishPage()`, the
finalize route's `error-code` append, and the edit-order and update-order routes match 6.7 in name, path and
redirect behaviour. 6.5's asynchronous handlers must return a redirect, so breaking out of the frame for
every order remains correct.

## Verification

- **App:** `pnpm vitest run` passes 263 tests (256 before, plus 7 new). Typecheck adds no errors outside
  the existing implicit-`any` handler-argument class.
- **Connector static analysis:** phpstan level 9 is clean against the 6.5.6.1 vendor for PHP 8.2 and 8.1.
  Before the route change it reported 9 `attribute.notFound` errors.
- **Connector tests:** the unit suite passes against 6.5.6.1.
- **Connector on a local 6.5.6.1 instance:** all five routes register. A guest cart minted into a handoff
  code redirects to `/checkout/confirm`, a replayed code answers 400, and the confirm page carries the
  navigation id.
- **Request replay:** each changed app request was replayed against the local 6.5.6.1 instance.
